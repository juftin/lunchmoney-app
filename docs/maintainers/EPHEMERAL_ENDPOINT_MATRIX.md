# Ephemeral and Stateful Endpoint Capability Matrix

## Purpose

This matrix turns the approved runtime design into endpoint-level obligations.
Implementers must update a row before changing its classification or acquisition
strategy. The architectural source of truth remains
[`DESIGN_EPHEMERAL_STATEFUL.md`](DESIGN_EPHEMERAL_STATEFUL.md).

REST paths below include the `/api` prefix unless noted. MCP tools with the same
operation name must delegate to the same service behavior. A direct upstream
method name refers to the generated Lunch Money client pinned by the project.

## Classification

- **Both**: Available in stateful and ephemeral modes.
- **Stateful only**: Returns `stateful_mode_required` in ephemeral mode.
- **Operational**: Available in both modes but does not create a data operation.
- **Projection**: Work performed only after Lunch Money accepts a mutation.
- **Operation invalidation**: Request-local memoized reads invalidated in both
  modes after a successful mutation.

Every stateful reader returns canonical `lunchmoney.models` objects rather than
SQLModel records. Every ephemeral acquisition uses `cache=False` or an equivalent
non-retaining client path.

## Stateful-Only and Operational Surfaces

| Surface                                                          | Classification | Required behavior in ephemeral mode                                                                                                               |
| ---------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /sync`, MCP `sync_data`, foreground `sync` command         | Stateful only  | Raise `stateful_mode_required`; REST maps to 409, MCP to an error result, CLI exits nonzero. Do not resolve storage or acquire a sync lock first. |
| `GET /sync/status`, MCP `get_sync_status`                        | Stateful only  | Same mode error; do not query `ScheduledSyncRun`.                                                                                                 |
| Dedicated scheduler and embedded scheduler                       | Stateful only  | Configuration validation fails before startup.                                                                                                    |

| `POST /dashboard/sync`                                           | Stateful only  | Return the documented JSON 409 mode error before sync or rendering.                                                                               |
| Future cache freshness, watermark, or scheduled-history surfaces | Stateful only  | Use the same mode error consistently.                                                                                                             |
| `GET /health`, `GET /healthz`                                    | Operational    | Report liveness without constructing a database or probing Lunch Money.                                                                           |
| `GET /ready`, `GET /readyz`                                      | Operational    | Validate application configuration only; no database query and no upstream availability dependency.                                               |

| MCP prompts                                                      | Operational    | Remain available; prompts contain instructions only and create no operation context.                                                              |

## Projection-Failure Rule

For every stateful mutation row, Lunch Money success is authoritative. If its
projection fails:

1. Return the successful upstream result or the normal success response.
2. Do not automatically retry the mutation.
3. Mark the affected cache domain stale and emit safe health telemetry.
4. Persist the stale marker when storage permits so every worker observes it.
5. Degrade readiness if the stale marker itself cannot be persisted.
6. Allow later synchronization to reconcile the affected domain.

No ephemeral mutation invokes persistent projection or stale-marker storage.
